1. THEORY AND MATHEMATICS
--------------------------------------------------------------------------------
1.1 Where metadata lives
  MP4/MOV   'moov' atom: at byte 0 (FastStart) or at EOF (typical recorder output).
  MKV/WebM  EBML header, SeekHead, Info, Tracks: near the start of the file.
  AVI       RIFF 'hdrl' list: first ~64 KiB.
  The payload ('mdat' / Clusters) is >99.8% of the file and is never read.

1.2 The bridge
  Telegram file  --(MTProto, 1 MiB chunks)-->  Source.read_range()
                 --(HTTP 206, 127.0.0.1)----->  aiohttp loopback server
                 --(http://127.0.0.1:PORT/stream/TOKEN)--> ffprobe (subprocess)

  ffprobe only knows it is reading an ordinary HTTP URL that supports Range.
  It seeks like a normal player; every seek becomes a new Range request that the
  bot answers by fetching only the needed chunks.

1.3 Chunk alignment mathematics
  Let C = 1,048,576 (1 MiB) and a request Range: bytes=start-end (inclusive).

      start_chunk     = floor(start / C)
      end_chunk       = floor(end   / C)
      chunks_to_fetch = end_chunk - start_chunk + 1

  Pyrogram/Pyrofork: client.stream_media(message, offset=start_chunk,
                                         limit=chunks_to_fetch)
  (offset and limit are in CHUNKS, not bytes.)

  For chunk index i (start_chunk <= i <= end_chunk), with chunk bytes chunk_i:

      slice_start = max(0, start - i*C)
      slice_end   = min(len(chunk_i), end - i*C + 1)
      emit chunk_i[slice_start:slice_end]

  Worked example: Range bytes=1048570-1048600
      start_chunk = 0, end_chunk = 1, chunks_to_fetch = 2
      i=0: slice_start = 1048570
           slice_end   = min(1048576, 1048600-0+1) = 1048576
           emits bytes 1048570..1048575 (6 bytes)
      i=1: slice_start = max(0, 1048570-1048576) = 0
           slice_end = min(len, 1048600-1048576+1) = 25
           emits bytes 0..24 of chunk 1 (25 bytes)
      total = 31 bytes = (end - start + 1). Verified by unit test.

  Open-ended / full-file ranges (bytes=0-) are streamed lazily: chunks are only
  pulled as the socket drains, and the generator is closed the instant ffprobe
  disconnects, so no further chunks are fetched.

1.3 Bandwidth example (4 GB file, moov at EOF)
  ffprobe reads ~32 KB at start, sees 'mdat', seeks to EOF, reads the last chunk.
  Bandwidth: 1-3 MiB of 4096 MiB (< 0.1%), 0 bytes written to disk. Note the
  granularity is 1 MiB, so even a tiny read costs one whole chunk.

2. DEPLOYMENT
--------------------------------------------------------------------------------
Prerequisites: Python 3.11+ (3.12 recommended), FFmpeg (provides ffprobe),
               API ID/HASH from https://my.telegram.org, bot token from @BotFather.

2.1 Local virtualenv - Linux / macOS
    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    cp .env.example .env        # then edit .env
    python bot.py

2.1b Local virtualenv - Windows PowerShell
    py -3.12 -m venv .venv
    .\.venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    Copy-Item .env.example .env       # then edit .env
    winget install Gyan.FFmpeg        # or download from ffmpeg.org; ensure ffprobe is on PATH
    ffprobe -version                  # verify
    python bot.py
  (If activation is blocked: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned)

2.2 Linux systemd service  (/etc/systemd/system/mediainfo-bot.service)
    [Unit]
    Description=Zero-Download MediaInfo Telegram Bot
    After=network-online.target
    Wants=network-online.target

    [Service]
    Type=simple
    User=mediainfo
    WorkingDirectory=/opt/mediainfo-bot
    EnvironmentFile=/opt/mediainfo-bot/.env
    ExecStart=/opt/mediainfo-bot/.venv/bin/python bot.py
    Restart=on-failure
    RestartSec=5
    NoNewPrivileges=true
    PrivateTmp=true
    ProtectSystem=strict
    ProtectHome=true

    [Install]
    WantedBy=multi-user.target

  Commands:
    sudo useradd -r -s /usr/sbin/nologin mediainfo
    sudo chown -R mediainfo: /opt/mediainfo-bot && sudo chmod 600 /opt/mediainfo-bot/.env
    sudo systemctl daemon-reload && sudo systemctl enable --now mediainfo-bot
    journalctl -u mediainfo-bot -f

2.3 Dockerfile
    FROM python:3.12-slim
    RUN apt-get update && apt-get install -y --no-install-recommends ffmpeg \
        && rm -rf /var/lib/apt/lists/*
    RUN useradd -r -u 10001 bot
    WORKDIR /app
    COPY requirements.txt .
    RUN pip install --no-cache-dir -r requirements.txt
    COPY config.py bot.py ./
    USER bot
    CMD ["python", "bot.py"]

    docker build -t mediainfo-bot .
    docker run -d --name mediainfo-bot --restart unless-stopped \
        --env-file .env --read-only --tmpfs /tmp mediainfo-bot
  (The loopback server is inside the container; no ports need publishing.)

6. FAQ AND TROUBLESHOOTING
--------------------------------------------------------------------------------
Q: Why do I need a user session for 4 GB files?
A: Bot accounts are limited to 2 GB; Telegram Premium raises the limit to 4 GB
   for user accounts. Set TELEGRAM_USER_SESSION_STRING to a Premium account's
   Pyrogram session string. For files larger than 2 GiB the bot asks the user
   session to fetch the same message (user.get_messages(chat_id, message_id)).

Q: The user session can't see my file. What now?
A: A user account can only read messages in chats it belongs to. In a private
   chat with the BOT the Premium account is not a participant, so the bot falls
   back to its own client (which may fail for >2 GB). Fix: send/forward the file
   to a group or channel that BOTH the bot and the Premium account have joined.

Q: How do I generate a session string?
A: Run a one-off script with Pyrogram/Pyrofork:
       from pyrogram import Client
       with Client("gen", api_id=ID, api_hash=HASH, in_memory=True) as app:
           print(app.export_session_string())
   Log in with the Premium account's phone number, then store the string in .env.

Q: "ffprobe was not found".
A: Install FFmpeg and ensure ffprobe is on PATH, or set FFPROBE_BIN to its
   absolute path (Windows: C:\ffmpeg\bin\ffprobe.exe).

Q: "moov atom missing" / "could not recognise this as a valid container".
A: The upload was truncated, the file is corrupt/encrypted, or it is not a
   video. Re-upload the original.

Q: "Inspection timed out".
A: Slow datacenter or very large header. Raise PROBE_TIMEOUT_SECONDS (e.g. 60)
   or FFPROBE_PROBESIZE. MKVs with huge attachment/cue tables need more.

Q: External link rejected: "does not support HTTP Range requests".
A: By design. Without byte-range support the file cannot be inspected without
   downloading it, which this bot refuses to do.

Q: Link rejected as private/internal.
A: The host resolves to a loopback/RFC1918/link-local/metadata address. This is
   the SSRF guard and cannot be disabled via configuration.

Q: Log lines about ConnectionResetError / BrokenPipe?
A: These are suppressed on purpose: ffprobe closes the socket as soon as it has
   what it needs.

Q: "Missing required configuration".
A: TELEGRAM_API_ID, TELEGRAM_API_HASH and TELEGRAM_BOT_TOKEN are mandatory.

Q: Windows: process tree is not killed on timeout?
A: bot.py uses 'taskkill /F /T /PID'; run the bot from a normal (non-restricted)
   shell and make sure taskkill.exe is available (default on Windows).

7. FEATURES, COMMANDS AND TELEGRAPH OUTPUT (v2)
--------------------------------------------------------------------------------
7.1 MediaInfo as a link
  The full report is published to telegra.ph and returned as a link plus an
  inline "Full MediaInfo" button under a short summary.
  OUTPUT_MODE=telegraph  link only (automatic .txt fallback if Telegraph fails)
  OUTPUT_MODE=txt        .txt document only
  OUTPUT_MODE=both       link and .txt
  - One Telegraph account is auto-created on first use. To keep all pages under
    one account across restarts, put its access_token in TELEGRAPH_ACCESS_TOKEN.
  - Telegraph pages are limited to ~64 KB; huge reports are trimmed (chapters
    first, then trailing subtitle tracks) with a note on the page.
  - Telegraph must be reachable from the bot's server (api.telegra.ph).

7.2 Commands (v3: command-only)
  /mediainfo | /ml | /mi   reply to a video/audio file, or to a message with a link
  /mediainfo <link>        inspect a direct http(s) link
  (caption)                send a file with /mediainfo as its caption
  /start, /help            help text
  /stats                   owner only: uptime, inspections, cache hits, failures

7.3 Behaviour
  - NOTHING is automatic. Sending a file or a link without a command gets no
    reply and triggers no inspection, in private chats and groups alike.
  - The report is a graph.org link (Telegraph page). It opens inside Telegram
    (Instant View) or any browser - no download needed. Change the domain with
    TELEGRAPH_DOMAIN (graph.org or telegra.ph).
  - No .txt file is ever sent unless OUTPUT_MODE=txt/both or TXT_FALLBACK=true.
    If Telegraph fails the bot replies with the error reason. API hosts are tried in
    order (TELEGRAPH_API_URLS) with retries; a stale TELEGRAPH_ACCESS_TOKEN is replaced.
  - Audio files are supported (mp3, flac, m4a, aac, opus, ogg, wav, mka, ...).
  - Result cache: the same Telegram file or link within CACHE_TTL_SECONDS returns
    instantly with the same link and no new network reads. Link inputs still pass
    the SSRF check before the cache.
